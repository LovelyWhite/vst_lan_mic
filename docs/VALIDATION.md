# 人工验收清单

本次未代为编译、运行测试、刷机或连接手机。以下条目均为开发者后续验收项，不表示已经通过。

## 构建与枚举

- [ ] 用固定 PlatformIO 依赖完成固件构建，确认 Flash/PSRAM 配置符合实物。
- [ ] 确认固件没有打印 `Opus encoder initialization failed`，且 Opus 编码器状态
      成功分配到 PSRAM；记录启动后的 `minHeap`、`maxBlock` 和 `psramFree`。
- [ ] macOS Release、macOS Universal、Windows MSVC 分别完成两个 VST3 目标构建。
- [ ] 构建后 `LAN MIC Send.vst3`、`LAN MIC Return.vst3` 自动出现在 VST3
      插件目录，Studio One 重新扫描后能加载。
- [ ] Windows 删除旧版 bundle 并重新扫描后，只显示新插件；两个插件使用新的
      VST3 Class ID，打开后均能发现 `LAN MIC-XXXXXX`。
- [ ] 验证 Universal bundle 确实包含 arm64 和 x86_64；Windows 产物在对应架构 DAW 中扫描成功。
- [ ] 清除 NVS 后启动，无密码连接 `LAN MIC-<设备编号>` 开放热点，
      并从自动弹页或 `192.168.4.1` 完成 2.4 GHz Wi-Fi 配置。
- [ ] GPIO18 红色 LED 在连接 Wi-Fi 时快闪、配网时慢闪、联网待机时常亮，
      USB 音频传输时每秒短灭一次；长按 BOOT 3 秒后转为极快闪。
- [ ] 配网页面显示 `LAN MIC` 白色主题并直接进入 Wi-Fi 选择，
      不出现首页菜单、返回、退出、ESP 芯片信息、固件更新或网页清除入口。
- [ ] 不选择 Wi-Fi 时配网热点持续存在且页面不超时；保存有效凭据后才退出配网。
- [ ] 重启后设备直接使用 NVS 凭据连接；运行时长按 BOOT 约 3 秒并松开后，
      凭据被清除且设备重新进入配网。
- [ ] UART 日志打印 Wi-Fi 地址和设备身份，没有 USB 初始化或任务创建失败。
- [ ] Windows Studio One 中搜索状态显示至少 `1 IPv4 interface(s)`；同时启用
      Wi-Fi、以太网、VPN 或虚拟网卡时，仍能从 ESP32 所在接口发现设备。
- [ ] USB 音频设备、配网热点和 DAW 设备列表均显示 `LAN MIC-XXXXXX`，且三处
      `XXXXXX` 完全一致。
- [ ] Windows 网络配置为“专用”，Windows Defender 防火墙允许 Studio One 在
      专用网络收发 UDP；禁用 VPN 后的结果也记录在案。
- [ ] 双向流开启后 `usbTxPacket=192`；若为 196，USB IN 会按 49 kHz 消耗并周期欠载。
- [ ] 先接电脑检查 USB 描述符：UAC2、48 kHz、16 bit、输入输出各 2 通道，无原生 CDC。
- [ ] 再接目标 Android/iPhone，确认系统识别设备并在目标应用中使用外置输入输出。
- [ ] 分别记录系统版本、手机型号、转接器、USB 供电方式及应用版本。未测试的组合不标为支持。

## 单向与双向音频

- [ ] DAW 轨道发送低电平测试信号，经 `LAN MIC Send` 被手机录音应用录到。
- [ ] 仅打开 `LAN MIC Return`，手机播放能进入 DAW，不需要启动发送插件。
- [ ] 保存并关闭工程后重新打开，不打开 `LAN MIC Return` 编辑器也能自动连接并收到手机音频；
      无输入信号时宿主仍持续调用接收插件生成输出。
- [ ] 左右声道分别发送信号，确认上行平均下混、下行左右分离符合预期，无左右通道错位。
- [ ] 持续启用双向传输至少 30 分钟，记录欠载、丢包、裁剪计数和听感。
- [ ] 连续播放至少 30 秒，不再出现约 5 秒固定周期卡顿；连接期间不重建发现
      socket，ESP 串口在 USB TX/RX 活跃时不输出完整 `[DEBUG]` 快照。
- [ ] `post-fix-15` 日志中 `opusErr=0`，`opusBytes=480..480`，并确认 DAW 返回音频没有压缩杂音。
- [ ] iOS 播放并连续调节系统音量，`post-fix-17` 的 `usbVol=L/R` 随之变化；
      DAW 返回音量按听感均匀变化，最低档接近静音，且不再出现
      `USBAudioStreamBase setVolume` Warning。
- [ ] iOS 静音时 `usbMute=1/1` 且 DAW 返回静音；解除后平滑恢复。调节期间
      `usbRxDrop/under/udpFail` 不增长，Android 原有收发行为不回退。
- [ ] 稳态下 `udpFail`、`superseded`、`under` 不再增长；5 秒内下行约发送 250 个 Opus 包。
- [ ] DAW 到手机方向出现孤立丢包时，`upLost` 与 `upBridge` 同步增长，
      `under=0`、`usbTxDone=192..192`，且不出现端点直线插值导致的低频爆音。
- [ ] 人为造成短时下行丢包，确认 Opus PLC 平滑补偿且恢复边界无爆音；超过 300 ms 后不会追赶旧音频。
- [ ] 改变 Network gain，确认只调整手机录音音量且无突变，发送插件的本地原始输出不变。
- [ ] 检查应用切换、锁屏、USB 接口关闭/重新打开后能恢复，无旧声音重播。
- [ ] 防止手机声音返回发送总线导致反馈，首次验证使用低音量。

## 恢复与多实例

- [ ] 先开插件后启动 ESP32、先启动 ESP32 后开插件，都可以自动连接。
- [ ] 两个发送插件争用同设备，第二个明确显示 Busy；接收插件仍可独立连接。
- [ ] 关闭持有者或关闭 Network enabled，约 3.5 秒后其他实例可以取得方向。
- [ ] 多设备下，两个插件显式选择同一身份；保存并重开 DAW 工程后选择和参数保留。
- [ ] Wi-Fi 断开、AP 重启、DHCP 地址变化、ESP32 重启后可自动恢复。
- [ ] DAW 暂停处理较长时间再恢复，不播放长段旧音频，队列占用不会无限增长。
- [ ] 拔插手机时无任务卡死；接收音频停止后淡出为静音，上行可独立继续。
- [ ] 防火墙关闭访问、VPN 切换、访客网络隔离时给出可理解状态，不阻塞 DAW。

## 采样率与导出

- [ ] 分别在 44.1、48、88.2、96 kHz 工程中验证双向音高、时长和节拍一致，
      状态栏在非 48 kHz 时显示实际重采样方向且网络持续收发。
- [ ] 验证不同 DAW 块大小，包括非 672 整数倍；跨 block 不丢样、不重复，
      长时间运行后帧数不出现累计漂移。
- [ ] 在 16-bit、24-bit 和 32-bit float 工程设置下验证；网络 payload 始终为 PCM16，
      不要求或尝试改变 DAW 工程位深。
- [ ] 协议版本 7 的固件与两个插件一起升级；版本 6 工具和插件应被明确拒绝而非误解码。
- [ ] 离线导出不访问实时网络音频；需要手机声音时先实时录制到轨道。
- [ ] 发送旁路保留原始音频，接收旁路为静音；恢复网络功能后没有过期缓冲。

## 延迟测量

使用可重复的脉冲或扫频信号，录制参考与返回信号后按采样差测量往返延迟。
记录 DAW 块大小、网络拓扑、Wi-Fi RSSI、手机应用和测试时长，区分稳定延迟与波动范围。
不能简单把往返延迟除以二作为两个方向各自的延迟，因为两条链路处理可能不对称。

ESP32 麦克风方向和电脑接收方向均约 308 ms，均为网络接收起播缓存，
不是完整链路延迟。ESP32 到电脑方向还包含 20 ms Opus 组帧和编解码时间。
音频插件报告的 DAW 本地处理延迟为零，不尝试用固定 PDC 数字补偿可变的外部链路。

## 常见状态

| 现象 | 检查方向 |
| --- | --- |
| `Searching on 0 IPv4 interface(s)` | 本机没有可绑定的 IPv4 网卡，检查网卡状态和 IPv4 配置 |
| `Searching on N IPv4 interface(s)` | 已从 N 个接口广播；仍无设备时检查同网段、Windows 专用网络、防火墙和 AP 隔离 |
| Connecting | DAW 是否实际在处理、Network enabled、订阅返回包是否被阻挡 |
| Busy | 同一方向是否被另一个插件实例占用，等待租约到期 |
| Connected 但没有音频 | USB 流是否打开、手机应用输入选择、DAW 路由与监听 |
| RX 不增长 | 手机未向 USB 输出、USB 供电或连接问题、下行 UDP 被阻挡 |
| Under 持续增长 | Wi-Fi 丢包或调度不足、手机暂停发送、DAW 缓冲设置 |
| Trim 持续增长 | 时钟差过大、DAW 调度长期停顿或网络突发，检查两端实际采样率 |
| IO 持续增长 | 网卡/路由变更、socket 不可写、防火墙或系统网络错误 |
| `opusErr` 增长 | 编码输入帧或 Opus 状态异常；同时检查 PSRAM 与内部 RAM 是否充足 |
| `opusBytes=4294967295..0` | 尚未编码出首个下行包；先确认手机 USB OUT 与接收插件已连接 |
| 只有编辑器头文件红线 | 依赖尚未下载或 CMake/PlatformIO IntelliSense 尚未配置，不能据此认定已构建 |
| 插件目录没有新 bundle | 自动安装是否被 `SOS_COPY_VST3_AFTER_BUILD=OFF` 关闭、目录权限、DAW 是否仍占用旧 bundle |

通过上述清单后，再决定是否调整缓冲深度或更换 UAC 版本。降低缓存会提高欠载概率，
不应仅凭代码参数宣称零延迟或所有手机兼容。
